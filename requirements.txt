# Floor is 0.12.1: that release ADDED `nnx.Variable.get_value()` and deprecated
# the `.value` property in its favour. jcm reads every nnx.Param/nnx.Variable
# through `.get_value()` (~94 sites under jcm/physics/**), so on exactly 0.12.0
# the lookup misses the class and falls through `Variable.__getattr__` to the
# *wrapped* object — `AttributeError: 'SpeedyCoords' object has no attribute
# 'get_value'` as soon as a Model is built (#655). Do NOT "fix" that by moving
# to `.value`: that is the deprecated direction, and no flax ever released has
# both. (0.12.0 is unusable here anyway — it imports the long-gone private
# `jax._src.core.mutable_array`.)
flax>=0.12.1
# jax arrives transitively (via flax, dinosaur, jax-rrtmgp, ...) but jcm pins it
# DIRECTLY here because none of those declare an upper bound and the 0.11 line is
# broken for us: jax 0.11.x removed `jax.experimental.hijax.HiPrimitive`, which
# flax's nnx layer subclasses at *import* time
# (`flax/nnx/variablelib.py: class NewVariable(hjx.HiPrimitive)`), so `import flax`
# — and therefore `import jcm` — raises `AttributeError` on ANY flax against jax
# 0.11.x (verified for both 0.12.8 and 0.12.9). Without this bound a clean-env
# install on Python >= 3.12 deterministically resolves the newest flax (0.12.9,
# which itself requires jax>=0.11.1) onto jax 0.11.2 and cannot import; on Python
# 3.11 the break is only hidden because jax 0.11.x requires Python >= 3.12, so the
# resolver silently falls back to 0.10.2 — the fix must live in metadata, not rely
# on that accident. Capping flax alone is NOT enough (flax 0.12.8 breaks on jax
# 0.11.2 too); the untested-and-broken axis is jax, so we cap it. Floor 0.10 is the
# validated minor line (shared env and CI both run 0.10.2); revisit the ceiling
# once jcm is validated on jax 0.11+ (needs flax to also gain a jax upper bound or
# the hijax API to stabilise). See #853.
jax>=0.10,<0.11
